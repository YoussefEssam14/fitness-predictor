# Fitness Calorie Burn Predictor

A full-stack machine learning web app that predicts how many calories a workout burns. Users enter their details and workout, get an instant estimate from a polynomial regression model, save sessions to a log, and track progress on a dashboard.

**Stack:** scikit-learn · FastAPI · SQLAlchemy (SQLite) · React (Vite) · Recharts

---

## Features

- **Calorie prediction** from age, height, weight, gender, workout duration, and average heart rate
- **Workout log** that stores every saved session with its date
- **Dashboard** with total workouts, total calories, average per workout, and a weekly calories chart
- **Model page** that shows accuracy metrics and a "what-if" curve for how each input affects the prediction
- **Input validation** on both frontend and backend, restricted to the ranges the model was trained on

---

## How the model works

The model predicts calories from five numeric inputs and gender. It was built step by step, and each decision was driven by a measurement.

| Step | Finding |
|---|---|
| Data exploration | Duration, heart rate, and body temperature correlate strongly with calories |
| Drop `Body_Temp` | Users don't know their body temperature mid-workout. Removing it cost little (R² 0.967 to 0.959 on the linear model), so the web form stays realistic |
| Linear baseline | The residual plot showed a clear U-shape, meaning the relationship is curved |
| Polynomial features | Cross-validated MAE dropped from **9.55** (linear) to **3.14** (degree 2) to **2.27** (degree 3) |
| Ridge regularization | No improvement (3.14 vs 3.14, 2.27 vs 2.28). With 12,000 training rows and 5 base features there is little overfitting to correct, so it was left out |

**Final model:** `StandardScaler` → `PolynomialFeatures(degree=3)` on the numeric features, `OneHotEncoder` on gender, then `LinearRegression`, all inside one scikit-learn `Pipeline`. The pipeline is saved as a single file, so the API needs no separate preprocessing code.

**Test-set performance:** MAE ≈ `2.262025094807008`, RMSE ≈ `3.6750658082366865`, R² ≈ `0.9966534176082371` (printed by `train.py`, also shown on the Model page).

### Dataset

[Calories Burnt Prediction](https://www.kaggle.com/) on Kaggle: 15,000 workouts, CC0 license. Columns: `User_ID`, `Gender`, `Age`, `Height`, `Weight`, `Duration`, `Heart_Rate`, `Body_Temp`, `Calories`. The CSV is not included in this repository, so download it and place it at `ml/data/calories.csv`.

### Limitations

- The model is only reliable inside its **training ranges**: Age 20 to 79, Height 123 to 222 cm, Weight 36 to 132 kg, Duration 1 to 30 minutes, Heart rate 67 to 128 bpm. Polynomial models extrapolate poorly, so the API rejects inputs outside these ranges.
- The dataset has no exercise type, so the model cannot tell running from cycling at the same heart rate.
- The data covers short workouts (up to 30 minutes). Predictions are estimates, not medical or nutritional advice.

## Getting started

### Prerequisites

- Python 3.10+
- Node.js 18+ (LTS)

### 1. Train the model

```bash
cd ml
python -m venv venv
source venv/bin/activate        # Windows: venv\Scripts\activate
pip install pandas numpy scikit-learn matplotlib seaborn joblib jupyter

# place calories.csv in ml/data/, then:
python train.py

# copy the artifacts to the backend
cp model.joblib model_info.json ../backend/
```

### 2. Run the backend

```bash
cd backend
python -m venv venv
source venv/bin/activate
pip install fastapi uvicorn scikit-learn pandas joblib sqlalchemy

uvicorn main:app --reload
```

The API runs at `http://localhost:8000`, with interactive docs at `http://localhost:8000/docs`.

### 3. Run the frontend

```bash
cd frontend
npm install
npm run dev
```

Open `http://localhost:5173`.

## API reference

| Method | Endpoint | Description |
|---|---|---|
| GET | `/health` | Service status |
| POST | `/predict` | Predict calories for a workout |
| POST | `/workouts` | Predict and save a workout |
| GET | `/workouts` | List saved workouts, newest first |
| GET | `/workouts/{id}` | Get one workout (404 if not found) |
| GET | `/stats` | Total workouts, total calories, average calories |
| GET | `/stats/weekly` | Calories and workout count per week |
| GET | `/model-info` | Metrics, features, and training ranges |

### Example

```bash
curl -X POST http://localhost:8000/predict \
  -H "Content-Type: application/json" \
  -d '{"Age": 30, "Height": 175, "Weight": 70, "Duration": 20, "Heart_Rate": 100, "Gender": "male"}'
```

```json
{ "calories": 98.4 }
```

Out-of-range values return a `422` response that names the invalid field.

## What I learned

- Reading a residual plot to diagnose underfitting, and fixing it with polynomial features
- Using cross-validation to choose between models instead of trusting a single split
- Keeping preprocessing inside a scikit-learn `Pipeline` so training and serving cannot drift apart
- Validating inputs against the training distribution to avoid confident but meaningless extrapolation
- Building a typed REST API with FastAPI and Pydantic, and a React client that handles loading and error states
